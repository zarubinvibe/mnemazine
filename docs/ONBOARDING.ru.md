# Онбординг

Этот путь написан так, будто вы никогда не запускали локальную систему знаний. На каждом шаге сказано, что сделать и что вы должны увидеть.

Короткий путь — разговорный: откройте проект в Claude Code и запустите `/mnemazine-setup`. Мнемозина поставит себя сама, по одному вопросу, и ничего не поставит без вашего «да». Ниже — та же дорога пешком.

Нужны Node.js 20 или новее, Python 3.11 или новее и git. Лучше Mac: локальное распознавание скриншотов работает на Apple Vision и есть только там. На Linux работает всё остальное.

1. **Заберите проект в одну папку.**

   ```bash
   git clone https://github.com/zarubinvibe/mnemazine.git "$HOME/Desktop/Mnemazine"
   cd "$HOME/Desktop/Mnemazine"
   ```

   Вы увидите папку и приглашение терминала внутри неё.

2. **Посмотрите план до того, как что-то запишется.**

   ```bash
   MNEMAZINE_SETUP_DRYRUN=1 bash setup.sh
   ```

   Вы увидите, что установка сделала бы. Ничего не ставится и не перемещается.

3. **Запустите ведомую установку.**

   ```bash
   bash setup.sh
   ```

   У вас спросят, где будут входящие и нужен ли Telegram-бот. Локальные движки отвечают честно: которого нет, тот печатает строку об урезанной работе, а не притворяется установленным.

4. **Проверьте состояние.**

   ```bash
   npm run doctor
   ```

   Вы увидите зелёное или красную строку вместе с командой, которая её чинит. Код возврата 0 — всё зелёное, 2 — работает урезанно, 1 — что-то упало.

5. **Положите во входящие настоящий материал.** Скриншоты, PDF, сохранённую статью, голосовое. Пять-десять ваших файлов, а не выдуманный пример.

   Вы увидите их в одной папке, они ждут.

6. **Запустите прогон и смотрите на стадии.** Сторож делает снимок и хеширует каждый файл, локальные движки читают, факты получают источник, длинный материал режется на отдельные заметки, каждая ложится в свой раздел.

   Вы увидите заметки в `vault/`: у каждой понятный заголовок и источник, который можно проверить.

7. **Откройте базу в Obsidian.** Укажите ему папку `vault/`.

   Вы увидите разделы, связи между заметками и блок о том, чем заметка вам поможет.

8. **Положите тот же файл второй раз.** Возьмите файл, который уже обработан, и снова бросьте во входящие.

   Вы увидите, что он узнан по хешу и пропущен. Дубликат стоит ноль токенов — отсюда и берётся экономия.

9. **Прочитайте недельную сводку.** В ней то, что изменилось и на что стоит потратить время: знание возвращается к вам само, а не ждёт, пока его вспомнят.

10. **Осознанно решите про глубокий режим.** Выключен — прогон бесплатный и материал не покидает машину. Включён — содержание уходит выбранному вами провайдеру модели. Это ваш ответ, и его спрашивают, а не додумывают.

## Как обновляться дальше

Дальше, когда выйдет новая версия, не клонируйте заново: откройте проект в Claude Code и запустите `/mnemazine-update`. Он сначала покажет, что изменится, потянет изменения только вперёд, не тронет ваши настройки и данные и после обновления перепроверит себя.

## Если это помогло

Если Mnemazine превратила вашу кучу в то, чем вы правда пользуетесь, поставьте звезду: [https://github.com/zarubinvibe/mnemazine](https://github.com/zarubinvibe/mnemazine). Это секунда, а от неё зависит, найдут ли проект другие.

Вы прошли путь целиком, значит, вы и есть тот, кто может его улучшить. Дорога короткая: сделайте fork, заведите ветку, оформите commit, отправьте push и откройте Pull Request. Прямой push в `main` релизный gate отклонит.

Шаг соврал? Заведите issue на [https://github.com/zarubinvibe/mnemazine/issues](https://github.com/zarubinvibe/mnemazine/issues) и напишите, что запускали и что увидели.
