## English

Thanks for the detailed report. Filing all four in one issue was the right call: they do share a
root. The workaround you found was correct. All four are fixed in our source repository, and three of
them turned out to be worse than the issue described. The release that carries them into this
repository has not gone out yet, so a clone made today still has the old pins. Details at the end.

**1. Unsatisfiable pins.** You diagnosed the real mechanism: pip resolves the whole list at
once, so a single unbuildable pin leaves `.venv` with nothing but `pip`. Fixed in three parts:
`onnxruntime` moved to `1.23.2` (ships `macosx_13_0_x86_64` *and* `arm64`, and satisfies
`fastembed==0.8.0`'s constraint); `torch`, `openai-whisper`, `numba` and `llvmlite` moved to a
separate `requirements-media.lock` installed as a deliberate second step
(`MNEMAZINE_WITH_MEDIA=1`, ~1.1 GB, never fatal); and when a bulk install does fail, the
installer retries package by package so everything installable lands, then names each package
that did not, instead of collapsing all of it into one vague DEGRADED line. There is also a `MNEMAZINE_PIP_FORCE_FAIL=1`
switch so that degradation path runs on every machine, Intel or not.

We kept whisper reachable rather than dropping it: local transcription is one of the reasons
this project exists, so it is now an informed second step with an honest size warning.

**2. `graphify` not on PATH.** Fixed the way you suggested at the call site rather than with a
symlink: `runCommand` now prepends `<root>/.venv/bin` to `PATH`, which covers all three
`graphify` calls plus `graphify-mcp` in one place and survives moving the project. Verified by
running `graph:smoke` with `.venv` deliberately absent from `PATH`.

**3. `setup.sh` and exit code 2.** Fixed: only `1` (and anything above `2`) is fatal now. And
because "degraded" should not be taken on faith, `setup.sh` then actually runs
`graphify --version` and `markitdown --help` and reports which one works. There is a test that
runs both branches against the real text of `setup.sh`.

**4. Missing files.** Root cause was on our side of the publication pipeline, not a lost
commit: `demo/**` was never in the `include` list of our release surface, and
`scripts/check-public-release.sh` is deliberately excluded (it carries a private-marker map),
while `package.json` still referenced it as `public-check`, which is where exit 127 came from. `demo/**` is now
published, the `public-check` script and its doc references are gone from the public surface,
and internal callers invoke the script directly. Two more failures surfaced while checking
this: `demo-smoke` crashed with `ERR_MODULE_NOT_FOUND` because a module was missing from a
hand-maintained copy list, and the private-release gate was red on markers that had leaked
into published test fixtures. Both fixed.

**One correction to the issue.** The CI job cannot use `macos-13`: GitHub retired that image on
2025-12-04. The x86_64 runner is `macos-15-intel`, available until August 2027.

**Where the fix is right now.** The work sits in our private source repository as `39a57de` and
`b42d8b1`, with the CI job that should have caught this on `40f4996`: it installs the lock for real on
an x86_64 runner every week, which is the check that was missing. The public release is held by our
own release gate on a separate matter, visual and README requirements that have nothing to do with
these four bugs. We are not going to wave a gate through to look faster. Until the release lands your
workaround is the right one: `onnxruntime` at `1.23.2`, and `torch`, `openai-whisper`, `numba` and
`llvmlite` kept out of the main install. We will write here the day it ships.

If you have a moment, a fresh clone on your Intel Mac would confirm it better than anything we can
run: nobody else here has that hardware. And a PR is welcome any time; the offer is
appreciated.

**1. Пины без колёс.** Вы точно назвали механизм: pip разрешает список целиком, поэтому один
неустановимый пин оставляет `.venv` с одним `pip` внутри. Починка из трёх частей. `onnxruntime`
переехал на `1.23.2`: у него есть колёса и под `macosx_13_0_x86_64`, и под `arm64`, и он проходит
ограничение `fastembed==0.8.0`. `torch`, `openai-whisper`, `numba` и `llvmlite` вынесены в отдельный
`requirements-media.lock`: это осознанный второй шаг (`MNEMAZINE_WITH_MEDIA=1`, около 1.1 ГБ), и его
отказ никогда не роняет установку. А если пакетный заход всё-таки падает, установщик идёт вторым
кругом по одному пакету: встаёт всё, что может встать, и каждый непоставленный называется по имени,
а не сводится к общей строчке про урезанные возможности. Есть и переключатель `MNEMAZINE_PIP_FORCE_FAIL=1`,
чтобы ветка деградации гонялась на любой машине, а не ждала Intel.

Whisper мы не выкинули, а сделали шагом с честным предупреждением о размере. Локальная расшифровка
остаётся одной из причин, по которым проект вообще существует.

**2. `graphify` не находился.** Починили там, где вы и предложили, в месте вызова, а не симлинком:

и `graphify-mcp`, и переезд проекта это переживает. Проверено прогоном `graph:smoke` с `.venv`,
намеренно убранной из `PATH`.

**3. `setup.sh` и код 2.** Теперь провалом считаются только `1` и всё, что больше `2`. И раз уж

который гоняет их по настоящему тексту `setup.sh`.

**4. Пропавшие файлы.** Причина оказалась на нашей стороне конвейера публикации, а не в потерянном
коммите: `demo/**` никогда не был в списке `include` публичной сборки, а `scripts/check-public-release.sh`
вырезан намеренно, в нём карта приватных маркеров. При этом `package.json` продолжал ссылаться на него
как на `public-check`, отсюда и код 127. Теперь `demo/**` публикуется, `public-check` убран из публичной
поверхности вместе со ссылками в доках, а внутренние вызовы идут прямо к скрипту. По дороге всплыли ещё

## 中文

感谢你写得如此详细的报告。把四个问题放在同一个 issue 里是对的，它们确实来自同一个根源。你找到的临时办法也没有错。
四个问题都已在我们的源仓库中修复，其中三个的实际情况比 issue 里描述的更严重。
不过，把它们带到这个仓库的发布还没有发出：今天克隆这个仓库，拿到的仍然是旧的版本锁定。细节见文末。

**1. 无法安装的版本锁定。** 你指出的机制是对的：pip 会把整份清单一次性求解，因此只要有一个装不上的包，
`.venv` 里最后就只剩下 `pip`。修复分三部分。`onnxruntime` 改为 `1.23.2`，它同时提供
`macosx_13_0_x86_64` 和 `arm64` 的 wheel，并且满足 `fastembed==0.8.0` 的版本约束。
`torch`、`openai-whisper`、`numba` 和 `llvmlite` 移到独立的 `requirements-media.lock`，
作为一个明确的第二步安装（`MNEMAZINE_WITH_MEDIA=1`，约 1.1 GB），它失败时绝不会中断整体安装。
如果批量安装仍然失败，安装脚本会改为逐个包重试：能装的全部装上，装不上的逐一点名，
而不是只留下一行含糊的 DEGRADED。另外还加了 `MNEMAZINE_PIP_FORCE_FAIL=1` 开关，
让降级分支在任何机器上都能跑到，而不只在 Intel 机器上。

我们没有直接删掉 whisper，而是把它变成一个带有真实体积提示的第二步：本地语音转写正是这个项目存在的理由之一。

**2. `graphify` 不在 PATH 上。** 按你的建议在调用处修复，而不是加符号链接：`runCommand` 会把
`<root>/.venv/bin` 放到 `PATH` 最前面。一处改动覆盖全部三个 `graphify` 调用和 `graphify-mcp`，
并且项目移动位置后依然有效。验证方式是把 `.venv` 故意从 `PATH` 中移除后运行 `graph:smoke`。

**3. `setup.sh` 与退出码 2。** 现在只有 `1`（以及大于 `2` 的值）才算失败。而且「部分功能不可用」这种话
不该只靠嘴说，`setup.sh` 随后会真的执行 `graphify --version` 和 `markitdown --help`，并报告哪一个可用。
两条分支都有测试，测试直接跑在 `setup.sh` 的真实文本上。

**4. 缺失的文件。** 根源在我们的发布流水线，而不是丢失的提交：`demo/**` 从来就不在发布清单的 `include` 里，
而 `scripts/check-public-release.sh` 是被刻意排除的，它里面有一份私有标记清单。与此同时
`package.json` 仍然以 `public-check` 的名义引用它，于是出现退出码 127。现在 `demo/**` 会被发布，
`public-check` 及其文档引用已从公开内容中移除，内部调用直接指向脚本本身。检查过程中还暴露了另外两个故障：
`demo-smoke` 因为手工维护的复制清单漏了一个模块而抛出 `ERR_MODULE_NOT_FOUND`，
私有发布门禁则因为泄漏进公开测试夹具的标记而报红。两者都已修复。

**对 issue 的一处更正。** CI 任务不能使用 `macos-13`：GitHub 已于 2025 年 12 月 4 日下线该镜像。
x86_64 的 runner 现在是 `macos-15-intel`，可用到 2027 年 8 月。

**修复现在在哪里。** 这些改动位于我们的私有源仓库，提交为 `39a57de` 和 `b42d8b1`；本该在你之前就发现问题的
CI 任务是 `40f4996`，它每周在 x86_64 runner 上真正安装一次版本锁定，缺的正是这道检查。公开发布目前被我们
自己的发布门禁挡住，原因与这四个问题无关，是视觉与 README 方面的要求。为了显得快一点而放行门禁，我们不会做。
在发布出来之前，你的临时办法就是对的：`onnxruntime` 用 `1.23.2`，把 `torch`、`openai-whisper`、`numba`
和 `llvmlite` 排除在主安装之外。发布当天我们会在这里说一声。

如果你有时间，在你的 Intel Mac 上做一次全新克隆将是最好的验证，这里没有别人拥有这样的硬件。
