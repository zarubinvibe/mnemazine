# NOTE-SPEC — схема ноты Мнемозины (агент — первый читатель)

Спроектировано Fable 5 по решению владельца 2026-07-25: ноты пишутся в первую очередь для агентов
(владелец читает справки по запросу, не сами ноты), поэтому форма оптимизирована под машинное
чтение — предсказуемые заголовки, самое переиспользуемое сверху, плотный текст без декоративной воды.
Гейт этой спеки — `scripts/mnemazine-vault-quality-gate.mjs` (fail-closed: нота, не прошедшая
проверку, не записывается в раздел, а уходит в ретрай) — потому что пожелание шаблона исполняется
вероятностно, а код-гейт всегда.

## Frontmatter (машинный слой)

```yaml
---
title: "Название знания"
type: concept            # закрытый список ниже — гейт отвергнет неизвестный тип
subject: world           # self | world | mixed — «факт обо мне» / «факт о мире» / оба (§18 мастер-плана)
section: "08 AI и Инструменты"
data_class: pd           # НЕобязательное — закрытый список ниже (§17.8, П24). Класс машины-обработчика; поднимает, не опускает
source: "<basename исходника или local-media:hash16>"   # вход гейта полноты (reconciler грепает basename)
sources:                  # все исходники + URL первоисточников
  - "<basename>"
  - "local-media:<hash16>"
  - "https://…"
verified: подтверждён     # подтверждён | источник-не-найден | непроверяемо-методом | облако-недоступно | проверено-практикой | не-проверялось
run_id: "kb-…"
processor_model: "…"
created: 2026-07-25
updated: 2026-07-25
projects: [project-a, project-b]   # слаги из «99 Система/_ПРОЕКТЫ.md» — машинный ключ проектного среза
tags: []
supersedes: ""            # версионирование знания: новая нота помечает, что́ она заменяет,
superseded_by: ""         # старая получает обратную ссылку — историю пересмотра нельзя терять
---
```

Закрытый список `type` (незнакомое значение = провал гейта, потому что стихийные типы уже разъехались —
`level2-atom`, `knowledge-note`):

| type | Что это | Дополнительные обязательные поля |
|---|---|---|
| `concept` | понятие/метод/принцип | — |
| `tool-card` | карточка инструмента/сервиса | `repo`, `stars`, `license`, `risk` |
| `decision` | принятое решение с контекстом | `context`, `rejected` (список отклонённых вариантов с причиной) |
| `synthesis` | синтез из нескольких источников | — |
| `agent-research` | исследование агента проекта | `project`, `agent`, `claim_status: provisional\|graduated` |
| `reference` | указатель/реестр/индекс | — |

`verified: не-проверялось` (добавлено 2026-07-25) — только для СТАРОГО корпуса: 1235 нот пришли без поля
или со значением `false`, и ни одно из пяти прежних значений не описывает «никто не проверял». Впихнуть их
в `источник-не-найден` значило бы записать в корпус ложь ради зелёного гейта. Новая нота это значение
носить не должна — конвейер верифицирует материал до записи (стадия 3); ноты с ним отдельной волной
догоняются проверкой и меняют значение на настоящее.

`agent-research` рождается провизорным (`claim_status: provisional`) и смешивается с проверенным
корпусом только после операции graduate (ревью → `graduated`), потому что агентская верификация
обычно слабее владельческого конвейера.

`data_class` (§17.8 мастер-плана, П24) — **необязательное** поле закрытого списка
`public | infra | text | personal | pd`; незнакомое значение = провал гейта спеки (та же
механика, что у `type` — `scripts/mnemazine-vault-quality-gate.mjs` читает список из
`config/data-classes.json`, единственной правды о таксономии). Класс задаёт, **на какой машине
ноту разрешено обрабатывать**: `pd` (данные доверителей) и `personal` (личное владельца) — только
Mac и наружу не уходят; `text | public | infra` — Mac или VPS. **Отсутствие поля дефектом не
считается:** класс тогда берут правило по разделу (`by_section`) и наследование от источника
(`projects:`/`source:`) — механизм в `scripts/mnemazine-machine-class-gate.mjs`. Явное поле умеет
класс **поднять** и не умеет **опустить** (класс ноты = максимум по строгости среди сработавших
правил); понижение делается только переносом ноты в другой раздел — видимым действием с историей
в git корпуса, а не тихой строкой frontmatter. Простановка поля по корпусу — кампания П16, не запись П24.

`subject` (§18 мастер-плана) различает «факт обо мне» (`self`), «факт о мире» (`world`) и смешанное
(`mixed`). Значение вне этого списка — провал гейта всегда. Новая нота обязана нести поле (гейт требует
его в проходах с `--changed-since`); старый корпус до переогранки за отсутствие не карается. `subject: self`
при `source_type: video|article|repo` — провал: своим фактом обо мне нельзя объявлять пересказ чужого
источника (§18.4).

## Тело (порядок фиксирован — агент режет чтение сверху)

1. `## Короткий ответ` — 2–4 предложения, самодостаточные: агент, прочитавший только этот блок,
   уже может действовать.
2. `## Механика` — как и почему это работает (модель, математика, причины).
3. `## Применение` — готовая версия: команды, шаги, шаблон, конфиг.
4. `## Примеры и контрпримеры` — где работает и где похоже, но не работает.
5. `## Ошибки и границы` — известные грабли, пределы применимости.
6. `## Опыт практиков` — только с URL тредов/issues, потому что «практики жалуются» без ссылки непроверяемо.
7. `## 🎯 Как это поможет мне` — по именам проектов из `_ПРОЕКТЫ.md`; родовая фраза без имени
   проекта = провал гейта, потому что блок без привязки вырождается в шум.
8. `## Достоверность` — каждая строка самодостаточна (кто/когда/версия/URL) и читается вне контекста
   абзаца, потому что при атомизации и графовом разборе строка отрывается от окружения.
   Подраздел `### Рассмотрено и отклонено` — что проверялось и почему исключено: без него агент
   через месяц передумывает то же самое заново.
9. `## Связанные темы` — типизированные связи текстом: `расширяет [[X]]` · `противоречит [[Y]]` ·
   `предшествует [[Z]]` · `инструмент-для [[W]]`, потому что тип связи даёт обход графа без граф-БД.
10. `## Следующий ход` — конкретное действие, не «изучить глубже».

Атом (тонкая нота) законен: блоки 4–6 могут отсутствовать, но 1, 7, 8 обязательны всегда —
атом без короткого ответа, применимости и провенанса не находится и не проверяется.
Слияние атомов в досье — только явной операцией graduate после ревью, не автоматом по схожести.

## Язык и плотность

- Русский язык тела: доля кириллицы в прозе ≥ 30 % (гейт меряет), потому что владелец ищет по-русски
  и англоязычная нота для него невидима.
- Ключевой англоязычный термин несёт русскую формулировку того же понятия хотя бы один раз
  (`Payback → срок окупаемости`), потому что замерено: грep «срок окупаемости» не находил ноту про Payback.
- Плотный текст: без воды, без «в современном мире», каждый абзац оправдывает цену токенов.
- Один и тот же факт не повторяется дословно внутри ноты (внутринотный дедуп строк).

## Managed-блоки (канон дозаписи)

Дозапись факта в существующую ноту — только через
`<!-- MNEMOZINA_ATOM_START <stable-id> -->` … `<!-- MNEMOZINA_ATOM_END -->`,
потому что идемпотентный блок можно обновить повторным прогоном, а свободная дозапись плодит дубли.
Один источник может задеть несколько нот: связанная нота получает факт managed-блоком, а не третью
ноту-дубль.

## Когда НЕ по этой спеке

- Служебные файлы (`_МАСТЕР-ИНДЕКС.md`, `_ROUTING.md`, `_ПРОЕКТЫ.md`, логи) — у них свои форматы.
- Сырьё инбокса и архива — неизменяемо, конвейер его не редактирует никогда.
- Старые ноты до 2026-07-25 — не переганять массово; переогранка старой волны — отдельная
  Кими-кампания по решению владельца.
