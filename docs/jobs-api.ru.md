# Локальные задания Мнемозины

Один CLI обслуживает приложение macOS и адаптер Олимпуса. Node.js, без сервера и новых пакетов.

```sh
node scripts/mnemazine-jobs.mjs submit --kind search --query "память агентов"
node scripts/mnemazine-jobs.mjs submit --kind brief --query "память агентов" --mode deep
node scripts/mnemazine-jobs.mjs submit --kind ingest --file /absolute/document.pdf --mode deep
node scripts/mnemazine-jobs.mjs submit --kind ingest --text "https://www.youtube.com/watch?v=VIDEO_ID" --mode deep
node scripts/mnemazine-jobs.mjs submit --kind ingest --text "Название книги или тема" --mode deep
node scripts/mnemazine-jobs.mjs list
node scripts/mnemazine-jobs.mjs status --id UUID
node scripts/mnemazine-jobs.mjs cancel --id UUID
node scripts/mnemazine-jobs.mjs retry --id UUID
```

Каждая команда пишет один JSON в stdout. Ошибка: stderr и ненулевой exit code. `submit/status/cancel/retry` возвращают `{job}`, `list` — `{jobs}`. Поля задания: `id`, `kind`, `status`, `query`, `mode`, `project`, `provenance`, `files`, `created_at`, `updated_at`, `attempts`, `events`, `result`, `error`. Необязательные поля могут отсутствовать. Результат содержит `text` и `report_path`.

Статусы: `queued`, `running`, `completed`, `failed`, `cancelled`. Отмена выполняющегося задания сначала выставляет `cancel_requested`; окончательное `cancelled` появляется после остановки дочернего процесса. Повтор доступен для `failed/cancelled`; история попыток сохраняется. Отмена не откатывает уже записанные знания.

Ошибка обработки включает причину из состояния pipeline и путь к логу. Если текст извлечён, но после очистки короче 80 символов, приложение сообщает длину и просит добавить контекст. Этот отказ не означает, что файл не был прочитан; порог качества не ослабляется.

По умолчанию `mode=local`. Поиск и локальная справка работают без LLM, даже если окружение включает deep. Обработка файлов требует явного `--mode deep`: используется строгий desktop pipeline с enrichment и проверками перед архивом. Внешние вызовы выполняются через настроенных провайдеров. `--project` — метаданные, **не ACL и не ограничение поиска**. `--provenance` принимает JSON объекта для происхождения задания.

`--file` повторяемый. Текущий лимит — 512 MiB на файл, проверяется до чтения содержимого. Файл копируется в закрытый каталог задания, хэшируется SHA-256; оригинал остаётся на месте. Повтор той же группы содержимого с теми же project/provenance возвращает активное или завершённое задание с `deduplicated:true`. Новая версия файла — новое задание. Symlink в последнем компоненте входного пути отвергается. Снимки проверяются перед ingest. Pipeline получает отдельные inbox, state, reports, archive, cache/extracted. Существующий настроенный vault наследуется.

`--text` принимает ссылку http/https или название/тему, до 8 KiB UTF-8. Используется вместо файлов, только для ingest. Внешние пробелы удаляются; пустой ввод, управляющие символы, другие URL-схемы и URL с логином/паролем отвергаются. В задании сохраняются `input_text` и `input_kind` (`url/title`). Точный очищенный ввод и project/provenance определяют dedup.

Текст сохраняется прямо в `sources/*-research-request.md` как запрос на исследование с буквальным вводом и требованием не выдумывать факты. У такого элемента `files` нет `original`: внешнего временного файла нет. Это использует существующий путь `text-read → synthesize.publicSources/extractUrls → enrichPrompt(WebSearch/WebFetch) → atomize/verify`. Короткое название превращается в содержательный исследовательский запрос, а не в искусственно подтверждённую заметку. Успех зависит от найденных источников и существующих проверок. YouTube принимается как ссылка для исследования; скачивание видео и получение расшифровки по URL не гарантируются текущим pipeline.

`--root PATH` задаёт каталог очереди. По умолчанию `.mnemazine/state/jobs` внутри репозитория. Всем клиентам нужен один root. Блокировка очереди сериализует её worker. Дополнительная блокировка `.mnemazine-pipeline-lock` внутри канонического vault не допускает одновременной обработки через strict desktop pipeline и прямой `mnemazine-run.mjs`, в том числе из разных очередей. JSON состояния и история событий записываются одним атомарным rename с fsync. Это локальная очередь, не распределённая БД; каталог должен находиться на локальном диске.

`submit/retry` запускают отделённый worker. `list/status` также запускают его при наличии queued/running, если не передан `--no-start`; это позволяет приложению восстановить очередь после перезапуска компьютера. Worker остаётся ждать новые задания до остановки процесса; приложение может закрыться. Launchd пока не устанавливается. `work` восстанавливает задания умершего worker и повторяет попытку. Семантика at-least-once: если процесс погиб после записи в vault, часть действий может повториться. Снимок оригинала остаётся для разбора. Рабочие логи: `output.log` и `error.log` в каталоге задания.

Отмена останавливает process group pipeline и зарегистрированные отдельные группы LLM (TERM, затем KILL). Bridge пишет PID и время старта в `process-groups.jsonl`; перед сигналом проверяется идентичность процесса. Тот же журнал используется при восстановлении worker. Произвольные сторонние утилиты, отделившие новую сессию без регистрации, этим механизмом не покрываются. Отмена не гарантирует прекращение уже принятого удалённого запроса или откат vault. После прерывания блокировка vault сохраняется: следующая обработка откажет с кодом 75 до ручной проверки оставшихся процессов. Автоматического захвата старой блокировки нет.

Если лидер зарегистрированной группы умер, а группа ещё жива, принадлежность процессов после возможного повторного использования PID недоказуема. Очередь не убивает такую группу: задание получает `failed`, `recovery_blocked:true` и видимую ошибку. Worker не запускает следующие задания, retry также отказывает, пока неоднозначная группа существует. После её завершения доступен явный retry. Это безопасный отказ, а не обещание автоматического восстановления любой аварии.

Для тестов: `submit --no-start`, `retry --no-start`, `work --once`. Проверка: `node tests/test-jobs.mjs` — только временные фикстуры, без обработки живого inbox и без LLM.
