# Мнемозина в Олимпусе: адаптер координатора

`scripts/mnemazine-olympuz.mjs` принимает исследование бога в ту же очередь, которую использует приложение Мнемозины. Отдельного сервера, базы и доступа богов к vault нет. Координатор вызывает CLI через `execFile` / `Bun.spawn` с массивом аргументов, без shell.

В существующем Олимпусе `Registry` пока вызывает `forwardResearchRequests` из `src/research-inbox.ts`: старый перенос в inbox продолжает работать. Этот адаптер в Олимпус ещё не подключён. При подключении нужно заменить старый вызов для выбранного запуска, иначе один материал попадёт в оба пути.

## Передать материал

Команда координатора (пути ниже служат примером; подставляются из доверенной конфигурации):

```sh
node /opt/mnemazine/scripts/mnemazine-olympuz.mjs submit \
  --root /var/lib/mnemazine/state \
  --god athena --run run-123 --project example --mode deep \
  --worktree /srv/olympuz/worktrees/athena-run-123 \
  --file /srv/olympuz/worktrees/athena-run-123/research/agent-research--example--retrieval.md
```

`--root` должен совпадать с root приложения и worker. Это каталог состояния ядра, не путь vault. Координатор берёт `god`, `run`, `project` и `worktree` из своего Registry; бог не задаёт их через содержимое заявки. CLI не проверяет личность процесса: граница доступа по-прежнему обеспечивается песочницей Олимпуса. Запрещено отдавать богам этот CLI, общий root или произвольный запуск команд на хосте.

Intake требует явный `--mode deep`, поскольку штатный конвейер использует внешние модели. Координатор выставляет его только в разрешённом владельцем режиме обработки. Без флага заявка отклоняется до чтения файла.

Принимается один обычный файл из непосредственного `worktree/research/`, имя `agent-research--PROJECT--SLUG.md`, до 256 KiB. Симлинки, hardlink и несовпадающий проект отклоняются. Адаптер читает ограниченный снимок, добавляет стабильный штамп `god/run/project` и передаёт его штатному jobs core. Время приёма хранится в `job.created_at`, исходный файл сохраняется. Повторная доставка того же содержимого с тем же происхождением возвращает существующий `job.id`, если задача ожидает, выполняется или завершена. Для отменённых и упавших задач доступен явный `retry`. Координатор записывает соответствие `(run, source) → job.id` из квитанции.

Ответ stdout: один JSON `{ "job": { "id": "…", "kind": "ingest", "status": "queued", "provenance": { "client": "olympuz", "god": "athena", "run": "run-123", "project": "example" }, "result": null, "citations": [], "error": null } }`. Есть также `created_at` и `updated_at`. Ошибка: ненулевой exit code и JSON `{"error":"…"}` в stderr.

## Состояние, отмена, повтор

```sh
node /opt/mnemazine/scripts/mnemazine-olympuz.mjs status \
  --root /var/lib/mnemazine/state \
  --god athena --run run-123 --project example --id JOB_ID
```

`cancel` и `retry` вызываются так же. Перед действием адаптер сверяет все поля происхождения задачи. Чужая задача, включая созданную приложением владельца, возвращает `JOB_SCOPE_MISMATCH`. Повтор возвращает актуальный `job.id`: координатор сохраняет его из ответа. `--no-start` оставляет задачу в очереди для тестов или отдельного worker; в обычной работе его не передают.

В результате завершённого intake возвращается квитанция `result: {"accepted":true}`. Это не признание исследования достоверным: материал проходит действующие проверки конвейера, агентские утверждения остаются предварительными до предусмотренного ревью. Логи обработки и пути личного vault богам не выдаются. `citations: []` явно означает, что квитанция не содержит найденных источников.

## Поиск и справки

Команды `search` и `brief` пока отвечают `PROJECT_SCOPE_UNAVAILABLE` до вызова поиска. Поле `--project` в jobs core хранит происхождение; оно не ограничивает доступ к документам. Выдавать общий vault по такому фильтру нельзя.

Следующее условие подключения поиска: ядро должно проверять разрешённый корпус по доверенной конфигурации координатора и возвращать ссылки только на разрешённые источники. После этого адаптер сможет отдавать справку и citations. До тех пор владелец пользуется поиском приложения; боги получают только явно подготовленный координатором материал.

## Проверка без личных данных

```sh
node tests/test-olympuz-adapter.mjs
```

Тест создаёт временный общий root и публичный текст, обращается через клиент Олимпуса и прямой jobs CLI, проверяет видимость одной очереди, повторную доставку после смены времени, отмену, повтор, provenance и отказы при чужом запуске или опасном файле. Worker, LLM, сеть и живой vault не запускаются.
