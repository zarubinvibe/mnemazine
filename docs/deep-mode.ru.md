# Deep-режим (атомизация + проверка)

У Mnemazine два режима работы:

- **Консервативный (по умолчанию):** только локально. Без сети, без LLM, без внешних сервисов. Так работают `node scripts/mnemazine-run.mjs` и `npm run synthesize` по умолчанию.
- **Deep (по запросу):** использует LLM-агента (авто-выбор: Claude, иначе Codex), чтобы разбить один источник на много сфокусированных заметок (README «один источник → ~20 заметок») и проверить утверждения по их источникам.

Deep-режим **выключен, пока вы его не попросите**. Ничто в стандартном конвейере не выходит в сеть и не зовет LLM.

## Включение deep-режима

```bash
# рабочий запуск Desktop Inbox, строгий полный протокол:
npm start
# после setup.sh, если ~/.local/bin есть в PATH:
mnemazine

# весь прогон, deep:
node scripts/mnemazine-run.mjs --deep
# или через env (форвардится в synthesize):
MNEMAZINE_DEEP=1 node scripts/mnemazine-run.mjs

# только синтез, deep:
npm run synthesize -- --deep
```

Для рабочего Desktop Inbox используй `npm start` или `mnemazine`. Он сам читает `.mnemazine/config.local.sh`, берет inbox с рабочего стола, пишет в личный vault (`$MNEMAZINE_VAULT`), включает `--deep`, требует атомизацию + обогащение и после этого запускает `complete-check`. Desktop-gate проверяет заметки, измененные в этом проходе; полный аудит всего vault запускается отдельно через `npm run quality`.

Если deep-режим запрошен напрямую, но движок LLM недоступен, обычный `node scripts/mnemazine-run.mjs --deep` откатывается на локальный шаблонный синтез и сообщает `degraded: true` в JSON-выводе. Строгий запуск (`--require-deep` или `npm start`) в такой ситуации падает до архива.

## Мост LLM

Все вызовы LLM идут через один модуль: `scripts/mnemazine-llm.mjs` (`llmJson(prompt, schema, {provider, tools})`). **Жесткого списка движков нет.** Доступные CLI живут как данные в `config/cli-registry.json` (база: `claude`, `codex`, `kimi`) плюс gitignored-оверлей `config/cli-registry.local.json`. Подключить CLI — одна запись в JSON и ноль правок кода. `scripts/mnemazine-cli-router.mjs` валидирует реестр, сливает оверлей (тот может добавить CLI или подкрутить `model`/`effort`/`cost_tier`, но не пересадить `invoke`/`probe`/`data_classes`/`capabilities` базовой CLI и не выдать класс `pd`) и выбирает CLI по классу данных → возможности → тиру стоимости → доступности. Код ветвится по объявленной **возможности** выбранной записи, никогда по имени CLI.

Каждая запись реестра объявляет: `probe`/`invoke` (префиксы argv), `model`, `effort`, `data_classes`, `capabilities` (например `json_schema_inline`, `json_schema_file`, `json_in_prompt`, `web_search`, `stdin_prompt`, `long_context`), `cost_tier` (`cheap|standard|premium`) и `local`. Стадия, которой нужен веб-поиск, маршрутизируется только к носителю `web_search`; если такого нет — падение с названной причиной. Зафиксировать движок: `MNEMAZINE_LLM=<имя-записи>` (дефолт владельца задается в `.mnemazine/config.local.sh`).

### Переменные окружения

| Переменная | По умолчанию | Назначение |
|----------|---------|---------|
| `MNEMAZINE_LLM` | дефолт реестра | Фиксирует запись реестра по имени (`codex`, `claude`, `kimi`…). Не задан — роутер выбирает из реестра, предпочитая доступный бинарь. |
| `MNEMAZINE_<ИМЯ>_BIN` | авто-поиск | Переопределяет бинарь записи `<ИМЯ>` (например `MNEMAZINE_CLAUDE_BIN`, `MNEMAZINE_CODEX_BIN`). Иначе: env → login-shell PATH → типовые пути установки → голый PATH. |
| `MNEMAZINE_LLM_TIMEOUT_MS` | `420000` | Таймаут одного вызова. |
| `MNEMAZINE_DEEP` | не задано | `1` включает deep-режим (enrich + атомизация + проверка + digest). |
| `MNEMAZINE_ENRICH` | `1` в deep | `0` (или `--no-enrich`) пропускает стадию обогащения. |
| `MNEMAZINE_STRICT_ARCHIVE` | `1` в строгих прогонах | `0` разрешает архив с необогащенными заметками. По умолчанию строгий прогон требует verified enriched atoms. |
| `MNEMAZINE_MAX_ATOMS` | `20` | Лимит атомов на один кластер источника. |
| `MNEMAZINE_CONCURRENCY` | `4` | Размер роя для deep-исследования (параллельные агенты, ограниченно). |
| `MNEMAZINE_OWNER_CONTEXT` | общий | Контекст личных проектов для блока «почему важно» в справке. Либо положите в gitignored `.mnemazine/owner-context.txt`. |

### Распознавание (локально сперва, LLM-fallback)

Извлечение сначала пробует локальные движки за **0 токенов**: Apple Vision OCR (картинки), markitdown (PDF/DOCX/PPTX/XLSX/HTML), whisper + OCR кадров (видео). Только если локально ничего пригодного **и** включен `--deep`, файл распознает vision-LLM. Каждый файл изолирован — ошибка распознавания логируется, файл остается в inbox, остальной батч не ломается.

### Рой

В deep-режиме файлы/кластеры исследуются параллельно ограниченным пулом агентов (`MNEMAZINE_CONCURRENCY`, по умолчанию 4) — дешево и быстро. Упавшая задача не блокирует остальные.

### Обогащение (расширение знаний)

Перед атомизацией deep-режим запускает web-агента LLM, который **исследует и расширяет** захваченный материал «насколько реально полезно» — первоисточники, актуальные факты/версии, опыт практиков — каждый добавленный факт привязан к fetched-URL (антигаллюцинация). Атомы строятся из **расширенного** знания, не только из сырого захвата. Отключение: `--no-enrich` / `MNEMAZINE_ENRICH=0`.

Строгие прогоны (`npm start` / `--require-deep`) падают, если обогащения или проверки нет. Cached OCR сам по себе больше не открывает архив.

### Справка (русская человеческая сводка)

После Graphify `scripts/mnemazine-digest.mjs` (`npm run digest`) пишет в каждую заметку русскую **Справку** в стиле humanizer — *Что это / О чем / Почему важно мне / Связи* — плюс одну ноту-сводку прогона с картой всех атомов. Связи берутся прямо из метаданных заметок: атомы с общим `cluster_id` (родня из одного источника) и атомы с общим хостом source-URL. Детерминированно, без ключа модели. (`graphify update` строит только внутридокументный структурный код-граф; более богатые семантические связи нота↔нота потребовали бы отдельного прохода `graphify --update` и здесь не используются.) Это поверхность переиспользования: открыл одну заметку — понял знание и как оно связано. Идемпотентно (пропускает заметки со Справкой, если не `--force`).

### Атомизация (G4)

`scripts/mnemazine-synthesize.mjs` (с `--deep`/`--atomize`) отправляет каждый кластер источника в LLM и просит сфокусированные атомы — у каждого заголовок, что/зачем, пункты «как применить», следующее действие и поддерживающие URL источников. Каждый атом становится отдельной заметкой. Имена файлов — content-fingerprint (с привязкой к id кластера), поэтому повторные прогоны идемпотентны и не затирают существующие заметки.

### Проверка (G5)

`scripts/mnemazine-verify.mjs` присваивает каждой заметке `verification_status`:

- `unknown` — нет URL источника, подтверждающего утверждение;
- `assumed` — URL источника есть, но не запрашивался/не проверялся (**локальный** вердикт по умолчанию, без сети);
- `verified` — только при `--deep`: источник был достижим (HEAD/GET) **и** web-сверка LLM признала, что он подтверждает утверждение. Такие заметки получают `verified: true` и `status: final`.

В строгом прогоне файл уходит в архив только если найдена заметка с `verified: true`, `verification_status: "verified"`, `enrichment: "external-research"`, публичными URL и минимум двумя записанными внешними фактами.

## Безопасность

### Недоверенный ввод изолируется

Извлеченный материал (OCR, транскрипты, текст с сайтов) — **недоверенный**. Перед попаданием в любой промпт LLM он оборачивается `fenceUntrusted()` — делимитер инертных данных плюс явная инструкция, что содержимое нельзя исполнять как команды. Любое буквальное вхождение sentinel-метки внутри контента нейтрализуется. Это основная защита от prompt-injection через захваченный материал.

### Песочница

Backend Claude запускает `claude -p` без флага обхода разрешений; неразрешенные инструменты просто не выполняются. Backend Codex идет headless с `--sandbox read-only`, `--ask-for-approval never` и ephemeral-сессией. Web search включается только для deep-вызовов, где явно запрошены web-инструменты. Изоляция на уровне промпта все еще нужна, но backend-песочница теперь совпадает с local-first границей: inbox-контент можно анализировать, нельзя исполнять.

### Граница данных

Deep-проверка (`--deep`) отправляет текст утверждения и URL источников в LLM-агента, который делает web-поиск — поэтому локально полученный текст достигает внешних поисковых сервисов **только при `--deep`**. Консервативный режим по умолчанию этого не делает.

### Локальный скан секретов

`npm run release-check` (и `npm run public-check`) сканируют не только то, что может уйти в публику, но и локальный кэш извлечения (`.mnemazine/cache/extracted/`) на токен-подобные секреты (API-ключи, токены, приватные ключи), потому что захваченные скриншоты или PDF могут содержать креды, которые иначе утекли бы в синтезированные заметки. Захваченный секрет роняет гейт.
