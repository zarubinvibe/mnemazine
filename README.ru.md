**Mnemazine**: открытая персональная система памяти, названная в честь **Мнемозины**, греческой богини памяти и матери муз.

Идея простая. Большинство людей копят заметки, скриншоты и сохранённые ссылки, и больше к ним не возвращаются. Куча, не память. Настоящая память появляется, когда ты берёшь сырое, понимаешь его, проверяешь, связываешь с тем, что уже знаешь, и записываешь только то, что стоит сохранить. Mnemazine делает эту часть за тебя прямо в момент сохранения.

У приёма есть имя: **синтез на записи** (synthesis on write), его популяризировал [Андрей Карпаты](https://karpathy.ai/): не сваливай в надежде прочитать потом, а отжимай суть прямо при захвате, чтобы заметка была полезной уже при следующем открытии.

На практике Mnemazine берёт скриншоты, PDF, веб-страницы, YouTube-видео, заметки, гайды и GitHub-репозитории и превращает их в чистую, совместимую с [Obsidian](https://obsidian.md/) базу знаний. Сначала извлекает текст локально, хранит хэш источника (чтобы ты всегда знал, откуда факт), кладёт в vault только готовые заметки, связывает их в граф и не пускает сырой OCR и черновой мусор внутрь.

> Память, не свалка.

## Что это

Mnemazine: локальная система переработки входящих материалов в долговечные знания. Сырьё на входе, готовое знание на выходе.

Она не кладёт в vault сырой OCR, случайные имена файлов, скриншоты без контекста и непроверяемые копипасты. Вместо этого создаёт финальные заметки:

- понятный заголовок;
- ссылки на источники и статус проверки;
- атомизацию по темам, когда один источник содержит много идей;
- готовые к переиспользованию описания skills, инструкции агентам, заметки по реализации и действия для проектов;
- Graphify-карты для семантической навигации;
- еженедельные HTML-брифинги с локальным статусом: `read`, `work on it`, `forget`.
- визуальные отчёты после прохода: кластеры, малые атомы, учёт дублей и топ-20 рекомендуемых действий.

Цель проста: будущий ты не должен перечитывать двадцать скриншотов, целый гайд или сырой транскрипт. Будущий ты открывает одну хорошую заметку и сразу понимает, что это за знание, почему оно важно, как его применить и чем оно подтверждено.

## Как проходит установка — ты не потеряешься

Раздел стоит сразу после «что это» не случайно: до первого запуска стоит увидеть
установку целиком.

`setup.sh` ведёт по семи пронумерованным этапам, и каждый закрывается прежде, чем
начнётся следующий:

1. базовое окружение: git и Node.js 20+ (жёсткий гейт);
2. локальные движки распознавания: python3, ffmpeg, whisper, swiftc (по желанию;
   если чего-то нет, установщик печатает точную команду, а не бросает гадать);
3. куда класть inbox;
4. LLM-провайдер для deep-режима;
5. Telegram-бот;
6. сборка каркаса (`install.sh`);
7. готово, с точными следующими шагами.

Четыре вопроса заданы настоящими меню в терминале, дословно:

> Входящие материалы будут падать сюда: рабочий стол / внутри репозитория
>
> Найдены провайдеры. Чем работать? (Claude CLI / Codex CLI / Без deep — только локальный разбор)
>
> Подключить Telegram-бота? (шлёшь боту — падает в inbox)
>
> Есть VPS для бота?

Где возможности нет, установщик называет замену, а не падает: на не-macOS
устройстве Apple Vision OCR выключен, и картинки распознаёт LLM. Молча ничего не
пропускается. Прогон вхолостую, без единой правки на машине:

```bash
MNEMAZINE_SETUP_DRYRUN=1 bash setup.sh
```

`install.sh` (путь без вопросов) спрашивает один раз, прежде чем писать что-то за
пределами клона. Молчание считается отказом: он ничего не ставит и выходит с кодом
1. Обойти вопрос в автоматике: `MNEMAZINE_YES=1 bash install.sh`.

## Почему это экономит токены

Mnemazine экономит токены, вынося работу из повторяющегося LLM-контекста в долговечную локальную структуру: парсить локально, агрессивно кэшировать, хранить очищенные атомы, извлекать узко.

<p align="center">
  <img src="docs/assets/hero/mnemazine-token.png" width="760" alt="Экономика токенов: парсинг локально, hash-кэш, хранение атомов, узкое извлечение">
</p>

Типичная экономия складывается из:

- **Сначала локальное извлечение:** Apple Vision OCR, парсинг PDF, транскрипция, хэширование и перепись файлов выполняются локально, когда это возможно.
- **Hash-кэш:** повторные файлы обнаруживаются до обработки LLM. Дубликат стоит ноль модельных токенов.
- **Атомизация:** один длинный гайд может стать двадцатью сфокусированными заметками, и будущие промпты подтягивают только нужный атом.
- **Graphify-контекст:** агент может запросить граф вместо того, чтобы вываливать в контекст весь vault.
- **Только финальные заметки:** сырой OCR и шумные транскрипты остаются вне vault. Vault хранит сжатое, проверенное, человекочитаемое знание.
- **Еженедельные брифинги:** система показывает, что изменилось и что заслуживает действия, чтобы пользователь не просил модель заново переоткрывать прошедшую неделю.

В реальных сценариях это часто превращает огромные кучи источников в компактные переиспользуемые заметки. Точная экономия зависит от объёма источника, но рабочий принцип надёжен: парсить локально, агрессивно кэшировать, хранить очищенные атомы, извлекать узко.

## Установка

Склонируйте проект в единственную нужную папку:

```bash
git clone https://github.com/zarubinphil/Mnemazine.git "$HOME/Desktop/Mnemazine"
cd "$HOME/Desktop/Mnemazine"
bash setup.sh        # пошагово, с вопросами (куда класть inbox, опц. Telegram-бот)
# или: bash install.sh   # без вопросов, только каркас
```

`setup.sh` проводит новое устройство по этапам: проверяет окружение, чётко
говорит что доустановить если чего-то нет, спрашивает куда класть `inbox/`
(в репозитории или на рабочий стол), может задеплоить Telegram-бота на VPS.
Прогон вхолостую без изменений: `MNEMAZINE_SETUP_DRYRUN=1 bash setup.sh`.

`install.sh` ставит Python-пакеты из `requirements.lock`, если lock есть.
Политика обновления: правишь `requirements.txt`, пересобираешь/freeze'ишь lock
в `.venv`, коммитишь оба файла. Опциональные локальные движки пишут
`DEGRADED: ...`, а не изображают успешную установку.

Обновить уже скачанный проект:

```bash
cd "$HOME/Desktop/Mnemazine" && git pull --ff-only && bash install.sh
```

Обновить через чат агента:

```text
Mnemazine update
```

После установки откройте эту папку как Obsidian-vault:

```text
~/Desktop/Mnemazine/vault
```

По умолчанию проект лежит в `~/Desktop/Mnemazine`:

- `~/Desktop/Mnemazine Inbox`: сырые входящие, если в `setup.sh` выбран Desktop inbox;
- `inbox/`: repo-local входящие, если выбран inbox внутри репозитория;
- `vault/`: готовое знание;
- `reports/`: еженедельные HTML-брифинги;
- `.mnemazine/`: кэши, бинарники и локальное состояние;
- `skills/`, `agents/`, `workflows/`, `scripts/`: агентная система.

## Требования

- macOS рекомендуется для Apple Vision OCR.
- Linux работает для парсинга сайтов, обработки markdown, Graphify и операций с vault, но Apple Vision OCR пропускается.
- Node.js 20+.
- Python 3.11+.
- Git.
- Опционально: Obsidian, Claude Code, Codex, Cursor, OpenCode, Gemini CLI.

Установщик проверяет, что уже есть, и ставит то, что можно безопасно поставить локально. Он не требует приватных учётных данных.

## Запуск одной командой

Положите файлы в:

```text
~/Desktop/Mnemazine Inbox
```

Откройте в агенте папку проекта:

```text
~/Desktop/Mnemazine
```

Затем напишите в чате одно слово:

```text
Mnemazine
```

То же самое в терминале:

```bash
npm start
```

После `setup.sh` работает и короткая CLI-команда, если `~/.local/bin` есть в `PATH`:

```bash
mnemazine
```

Прогон делает:

1. перепись файлов;
2. SHA-256 дедупликацию;
3. локальное извлечение текста, когда возможно;
4. deep-атомизацию и расширение источниками;
5. создание финальной заметки с `source_ref` и `source_hash`;
6. gate качества vault;
7. перенос исходников в архив только после verified enriched atoms и зелёных gate;
8. guarded-попытку обновить Graphify;
9. обновление weekly HTML-отчёта;
10. report quality gate для обновлённого weekly HTML;
11. action brief в `.mnemazine/state/last-action-brief.md`;
12. визуальный post-run отчёт по знаниям в `reports/`.

`Mnemazine` / `npm start`: безопасный дефолт для настоящего inbox. Низкоуровневый `npm run run` оставлен для разработки и демо.

Проверить Desktop-путь без изменения live inbox и vault:

```bash
npm run protocol:desktop:dry-run
```

Перед настоящим live-прогоном запусти preflight:

```bash
npm run preflight:live
```

Он проверяет, что код чистый, `HEAD` совпадает с `origin/main`, LLM-провайдер
доступен, локальные security gates зелёные, Desktop dry-run проходит, а в inbox
есть активные файлы. Если preflight упал, `npm start` не запускай, сначала
исправь причину.

После live-прогона проверь итог:

```bash
npm run last-run -- --require-ok
npm run complete -- --require-deep
```

Быстрая проверка здоровья без обработки inbox:

```bash
npm run doctor
```

Если semantic Graphify task ещё работает, doctor покажет PID, elapsed time и путь к логу.
Чтобы дождаться остановки задачи:

```bash
npm run doctor:watch
```

Интервал опроса меняется через `-- --watch-interval-seconds 5`.

Тяжёлый аудит всего vault:

```bash
npm run doctor:full
```

Он добавляет полный human-layer по заметкам и final-vault проверки: raw-маркеры,
приватные имена путей, вложенный Graphify runtime и критические битые wiki-ссылки.
Для намеренно строгой проверки всех wiki-ссылок используй
`npm run audit:vault -- --wiki-scope all --strict-wiki`.

Перед ручной чисткой ссылок собери очередь:

```bash
npm run wiki:links -- --vault "$MNEMAZINE_VAULT"
```

Команда пишет `reports/YYYY-MM-DD-wiki-link-cleanup.{md,json}`: битые wiki-ссылки
сгруппированы по разделам, целям и исходным файлам. По умолчанию vault она не
меняет. Чтобы применить консервативный ремонт:

```bash
npm run wiki:links -- --vault "$MNEMAZINE_VAULT" --apply
```

`--apply` убирает placeholder/file/code-like wiki-синтаксис и создаёт русские
мостовые заметки для оставшихся отсутствующих целей. После этого проверь:
`npm run audit:vault -- --vault "$MNEMAZINE_VAULT" --wiki-scope all --strict-wiki`.

Если строгий прогон падает до архива, это нормально и безопасно: исходники
остаются в inbox. Не переносите и не удаляйте их руками. Читай
вывод `npm run last-run`, исправляй причину и запускай снова.

## Парсинг сайтов

Mnemazine умеет забирать сайт и превращать его полезные страницы в структурированные заметки:

```bash
node scripts/mnemazine-ingest-site.mjs --url https://example.com --apply --graphify --max-pages 40
```

Парсер ищет:

- подсказки sitemap в `robots.txt`;
- `sitemap.xml`;
- ссылки того же домена;
- заголовки страниц, описания, подзаголовки и основной текст;
- блоки JSON-LD;
- подсказки публичных API внутри same-origin JavaScript;
- ссылки на GitHub и на документацию.

По умолчанию он не использует приватные cookie или сессии браузера. Если сайту нужна авторизация, выгрузите данные сами и положите их в `inbox/`.

## Парсинг YouTube

Mnemazine умеет забирать YouTube-канал и превращать каждое видео в заметку-транскрипт, а затем автоматически подтягивать новые загрузки:

```bash
python3 scripts/kb-yt-harvest.py "https://www.youtube.com/@SomeChannel" --all --subscribe
```

Сначала он берёт субтитры (почти нулевая стоимость) и откатывается на локальный whisper, когда у видео нет пригодных субтитров. Каждое видео становится одной заметкой в inbox с именем `yt_<date>_<id>_<title>.md`. Подписанный канал затем опрашивается `scripts/kb-yt-watch.py` по RSS, забирая только новые загрузки, опционально по ежедневному расписанию launchd.

Он забирает только публичные видео и по умолчанию не использует cookie или сессии аккаунта. См. [Парсинг YouTube](docs/youtube-ingestion.ru.md).

## Контракт качества знаний

Vault должен содержать финальное знание, а не сырьё.

Каждая готовая заметка должна отвечать на вопросы:

- Что это?
- Почему это важно?
- Как это использовать?
- Где ссылки на источники?
- Что проверено, что предполагается, а что пока неизвестно?
- Какие skills, агенты, скрипты или проекты могут это переиспользовать?

Сырой OCR, скопированные фрагменты и шумные транскрипты отклоняются gate качества.

Gate качества также отклоняет типичный мусор сырого интейка: `intake-draft`, `draft-local`, `temp_image_*`, `IMG_*.PNG` и видимые расширения сырых картинок в тексте заметки. Папки вывода Graphify и бэкапы исключены из этой проверки качества заметок.

`npm start` запускает gate только по заметкам, изменённым в текущем inbox-проходе. Старый долг vault больше не блокирует архив новых файлов. Полный аудит всего vault остаётся ручным.

Запустить gate вручную:

```bash
node scripts/mnemazine-vault-quality-gate.mjs
```

## Отчёт знаний после прохода

После каждого полного прохода можно получить лёгкий визуальный отчёт в Markdown и HTML:

```bash
npm run postrun
```

Это не сырой лог, а справка по базе:

- какие полезные знания реально появились;
- как заметки распались на кластеры и малые атомы;
- какие дубли были учтены без мусорных заметок;
- какие 20 действий стоит взять первыми.

Если не передать JSON или логи конкретного прогона, отчёт читает свежие заметки из vault. Для точного отчёта по pipeline используйте `--results-json` или `--logs`.

## Навыки агентов

Репозиторий включает переносимые Agent Skills в стиле `.agents/skills`:

- `skills/mnemazine`: основной skill переработки знаний;
- `skills/local-doc-ops`: локальные помощники для документов/PDF.

Установщик может скопировать их в типовые места агентов, когда эти инструменты есть:

- `~/.codex/skills`;
- `~/.claude/skills`;
- проектный `.agents/skills`.

Skills безопасны для публикации: без персональных путей, приватных репозиториев, имён аккаунтов и секретов.

## Одинаковая работа Claude и Codex

Mnemazine устроен так, чтобы Claude Code и Codex выполняли один и тот же контракт знаний:

- одни и те же публичные скрипты в `scripts/`;
- одни и те же описания ролей в `agents/kb-pipeline/`;
- одинаковая дисциплина `source_ref` / `source_hash`;
- одинаковый quality gate до архивации;
- одинаковый визуальный отчёт после полного прохода.

Личности агентов являются частью workflow, а не украшением. Они описаны как публично безопасные паспорта ролей, чтобы Claude и Codex сохраняли одинаковые обязанности и стиль без приватных данных.

## Graphify

Graphify превращает vault в навигируемый граф связей. Mnemazine использует его для:

- поиска связанных заметок;
- извлечения с опорой на граф;
- еженедельных карт изменений;
- поиска дублей и почти-дублей идей;
- показа того, как один источник влияет на несколько областей знаний.

Для безопасных локальных обновлений используйте:

```bash
export MNEMAZINE_VAULT="/path/to/your/vault"
npm run graph:refresh -- --vault "$MNEMAZINE_VAULT" --mode auto
```

Эта обёртка держит `graph.json`, `GRAPH_REPORT.md`, backup/restore и `needs_update` в согласованном состоянии вместо слепого доверия одному тяжёлому семантическому прогону.

Живой `npm start` держит Graphify быстрым: обновляет code graph, оставляет
маркер `needs_update` и запускает семантическую экстракцию отдельной фоновой задачей. Проверяйте её так:

```bash
npm run graph:semantic:async
npm run graph:semantic:monitor
npm run graph:semantic:status
```

Для локальных семантических обновлений через Ollama она также использует защищённую лестницу моделей, отбраковывая модели, которые проваливают мини-смоук `graphify extract`, прежде чем они коснутся реального графа vault. API-backend тоже поддержан через переменные окружения вроде `OPENAI_API_KEY`, `ANTHROPIC_API_KEY` и `GEMINI_API_KEY`.

Дефолтный shard-путь умеет продолжать работу: завершённые shards пишут `.done.json`, а per-file cache лежит в `.mnemazine/semantic-cache`. `graph:semantic:monitor` безопасно продолжает pending/failed/dead задачи или старый `needs_update`; второй процесс при живом PID не запускает. Для чистого перезапуска: `npm run graph:semantic:async -- --fresh`.

Дефолты репозитория лежат в `config/graphify-refresh.json`. Переопределяйте их флагами CLI или env-переменными `MNEMAZINE_GRAPHIFY_*` по необходимости.

Удалённое зеркало `agent-os` использует явный allowlist в `config/athena-mirror-manifest.txt`. По умолчанию это dry-run:

```bash
export MNEMAZINE_MIRROR_DEST="root@YOUR_VPS_HOST:/srv/agent-os/"
export MNEMAZINE_MIRROR_SSH_KEY="$HOME/.ssh/your_key"
export MNEMAZINE_MIRROR_KNOWN_HOSTS="$PWD/.mnemazine/known_hosts"
npm run mirror:agent-os
npm run mirror:agent-os:apply
```

Зеркало сначала собирает payload во временную staging-папку, сканирует его на token-like секреты и отказывается копировать env-файлы, секреты, sessions, caches, reports и runtime state. `MNEMAZINE_MIRROR_KNOWN_HOSTS` включает строгую проверку host key; без него SSH использует обычные настройки клиента.

## Еженедельный HTML-брифинг

Еженедельный отчёт: это локальная HTML-презентация, по умолчанию на русском. Он сделан так, чтобы его было приятно читать, а не как сырой лог.

Каждую карточку можно пометить локально:

- `read`: оставить в vault;
- `work`: перенести в бэклог действий;
- `forget`: убрать или поместить в карантин из активного vault.

Состояние хранится в:

```text
~/Desktop/Mnemazine/.mnemazine/state/weekly-state.json
```

## Мои агенты

Прогон: это эстафета маленьких агентов с закреплёнными именами. Имена тут часть

## Бот: кидаешь файл — он в базе

Шлёшь боту что угодно: текст, фото, документ, голос, аудио, видео, и оно
попадает в `inbox/` Mnemazine. Установщик задаёт один вопрос:

> Подключить Telegram-бота? (шлёшь боту — падает в inbox)

Боту хочется быть всегда-онлайн, чтобы принимать пока устройство спит; это и
настраивает этап 5 `setup.sh`. Исходов три, у каждого свой выход: разворачивается
хост, печатается локальный бот для ручного запуска, или бот пропускается без
последствий.

Бот работает как транзитный буфер, а не как второе хранилище: машина сама забирает пришедшее
и обрабатывает локально; готовое знание живёт только в твоём vault.

Закрой бота на себя. На первом сообщении он логирует твой `chat_id`; поставь
`ALLOWED_CHAT_IDS=<твой_chat_id>` и перезапусти. Пустой список отвергает всех
(fail-closed), поэтому ненастроенный бот, который тебя игнорирует, это ожидаемо,
а не поломка. Полная настройка: [docs/telegram-intake.ru.md](docs/telegram-intake.ru.md).

## VPS: что он делает и как жить без него

Необязательный всегда-онлайн хост оправдывает себя тремя вещами:

- круглосуточный приём, пока Mac спит;
- сетевая добыча: скачать URL, снять снимок источника, RSS-радар, `yt-dlp`,
  вытащить текст из HTML и PDF;
- кампании по корпусу для классов данных `text`, `public`, `infra`.

Три вещи остаются на Mac, потому что их умеет только Mac:

- Apple Vision OCR: Swift-бинарь `.mnemazine/bin/vision-ocr`;
- расшифровка речи `whisper`;
- локальный модельный бэкенд `ollama`.

Обещать их где-то ещё значит разменять бесплатный локальный ярус на счёт от облака
за работу, которая сегодня стоит ноль, поэтому установщик такого не предлагает.

Чего хост не увидит никогда: заметки классов `pd` и `personal`. Классовый гейт
роняет любую такую отправку ненулевым кодом ещё до того, как она уйдёт с Mac.

Как жить без хоста: ответь «Нет VPS» на этапе 5. Бот тогда работает локально, пока
устройство включено (точная команда печатается), а всё остальное работает без изменений.

## Приватность: что уходит с твоего компьютера

Названо прямо, у каждого свой сторож, который его держит, а не обещание вести себя
хорошо. Наружу может уйти по четырём каналам, и каждый по умолчанию выключен или
огорожен.

| Канал | Что уходит наружу | Чем удержано |
|---|---|---|
| **deep-режим** | содержимое материала уходит в LLM выбранного провайдера | ответь «Без deep» на этапе 4; при выключенном deep — ноль токенов |
| **Telegram-бот + VPS** | токен бота, всё, что ты шлёшь боту, и весь локальный `reports/` | токен под `umask 177` в `.mnemazine/config.env`, закрыт `.gitignore`; хост пиннится по отпечатку (`known_hosts`, gitignored); удалённое состояние не меняется без явного флага; а гейт классов данных не выпускает наружу заметки `pd` и `personal` |
| **парсинг сайтов и YouTube** | только адрес, который ты сам дал на вход | пока адрес не дан, ничего не уходит |
| **зеркало agent-os** | только файлы из белого списка `config/athena-mirror-manifest.txt` | по умолчанию сухой прогон; env-файлы, секреты, сессии, кеши, отчёты и рантайм отвергаются |

Локально всегда остаётся: Apple Vision OCR, markitdown, whisper, хеширование и сам
корпус. Граница простая: при локальных движках разбор не покидает машину; без них
файл читает LLM.

Бот личный, не общий: это твой бот, а не мой и не единый на всех, и без него
система работает точно так же. Ответ «Нет» на вопрос про бота ничего больше не
стоит.

## Коды возврата

Каждая точка входа возвращает честный код, на который можно опереться:

- `bash install.sh` — 0 готово, 2 готово с недоступными возможностями, 1 не
  завершено; и 1, если отказать в согласии (ничего не поставлено).
- `npm run doctor` — 0 всё зелёное, 2 провалов нет, но есть предупреждения, 1 провал
  или ошибка. Каждая красная строка печатает команду, которая её чинит.
- `npm run release-check` — 1 при любом провале; 2, когда `--only` не выбрал ни одной
  известной проверки (пустая выборка никогда не печатается как «сдано 0/0»).

## Сломалось — что делать

Начни с короткого отчёта о последнем прогоне:

```bash
npm run last-run
```

Полное состояние последнего прогона пишется в
`.mnemazine/state/last-action-brief.md`, а HTML-отчёты падают в `reports/`.
Затем проверка здоровья: она читает последний прогон, ничего не обрабатывая:

```bash
npm run doctor
```

Каждая красная строка несёт точную команду, которая её чинит. Тяжёлый аудит всего
vault:

```bash
npm run doctor:full
```

Если строгий прогон остановился до архива, это by design: исходники всё ещё в
inbox. Не переноси их руками, почини причину и запусти снова.

## Безопасность

Этот публичный репозиторий намеренно исключает:

- содержимое приватного vault;
- скриншоты с персональными данными;
- API-ключи;
- SSH-хосты;
- имена аккаунтов;
- имена приватных проектов;
- локальные абсолютные пути с исходной машины разработки.

Перед публикацией релиза запускайте полный локальный gate:

```bash
npm run release-check
```

Он проверяет синтаксис скриптов, гоняет временный demo-интейк, проверяет архивирование-после-качества, запускает gate качества demo-vault, сканирует приватные маркеры/секреты и проверяет, что публичное описание и оба README остаются двуязычными.

Для локального offline-аудита во время разработки:

```bash
npm run audit:local
```

Он запускает syntax-check, security selftests, `npm audit`, `public-check` и static scan на опасные agent/SSH flags и credential-in-URL.
