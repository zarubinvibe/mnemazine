## 1. Guard — защита

```bash
VAULT="${MNEMAZINE_VAULT:?укажите путь к vault}"; INBOX="$HOME/Desktop/Mnemazine Inbox"
# Снапшот (точка отката, ДО любого mv)
git -C "$VAULT" rev-parse --git-dir >/dev/null 2>&1 || git -C "$VAULT" init .
git -C "$VAULT" add -A && git -C "$VAULT" commit -m "pre-kb-$(date +%Y%m%dT%H%M)" --allow-empty
SNAP=$(git -C "$VAULT" rev-parse --short HEAD)
# Lock (анти-гонка) — занят живым PID → BLOCKED
LOCK=/tmp/kb-run.lock
[ -f "$LOCK" ] && kill -0 "$(cat $LOCK)" 2>/dev/null && { echo "BLOCKED: прогон идёт (PID $(cat $LOCK))"; exit 1; }
echo $$ > "$LOCK"
# Durable-архив исходников (вне git-vault, БЕЗ авто-удаления — оригиналы нужны для claim↔источник ре-верификации)
ARCHIVE="$INBOX/_archive"; mkdir -p "$ARCHIVE"
# Зонд локальных движков извлечения (local-first, $0):
[ -x $HOME/.codex/skills/mnemazina/vision-ocr ] && echo ocr_ready        # Apple Vision OCR (картинки)
[ -x ~/.npm-global/bin/whisper ] && echo whisper_ready                # транскрипция видео/аудио
[ -x ~/.venvs/kb-embed/bin/python ] && echo embed_ready               # fastembed (дедуп)
```

- OCR — Apple Vision (не ollama/llava), транскрипция — whisper, эмбеддинги — fastembed; ollama для извлечения не используется, зондировать его не нужно.
- Git-команда упала — это не ошибка прогона: предупреди в выводе и продолжай, потому что перепись важнее точки отката, а о слабом снапшоте владелец узнает из твоего JSON.
- Lock занят живым PID — верни `lock:"BLOCKED"` и остановись; это не сбой, а штатная защита: два прогона в одном vault портят друг другу снапшот и hash-кэш.

## 2. Census — перепись (наземная правда)

```bash
find "$INBOX" -maxdepth 1 -type f -not -name README.md -not -name ".DS_Store" | sort
# для КАЖДОГО: shasum -a 256 "<файл>" → хэш; сверь с VAULT/99 Система/_processed-hashes.json
# хэш уже в кэше → cached:true (обработан ранее, скип за 0 токенов)
```

Хэш нашёлся в кэше → `cached:true` — это не пропуск работы, а её результат: файл обработан прошлым прогоном, скип экономит токены всего конвейера.

## Верни (JSON)
```
{ "snapshot", "lock":"acquired|BLOCKED", "ocr_ready", "whisper_ready",
  "embed_ready", "archive_path", "run_date",
  "files":[{"path","hash","cached","cached_note"}] }
```

## Правила

- Перечисли каждый файл (кроме README.md и .DS_Store), потому что census — наземная правда конвейера: файл, не попавший в перепись, исчезает молча, и никакие последующие ворота его уже не увидят.
- SHA-256 каждого файла со сверкой по кэшу, потому что хэш — единственный признак «уже обработан», не зависящий от имени и даты файла.
- Содержимое не читай и не интерпретируй, потому что смысл судит триаж (Сопиков), а чтение на стадии переписи жжёт токены и соблазняет пропустить «неинтересное».
- Снапшот до любого `mv`, потому что первое же перемещение меняет vault, а откат без снапшота невозможен.
- Имена файлов бери из вывода `find`, не перенабирай руками, потому что NFD-юникод и U+202F в именах не воспроизводятся набором — хэш посчитается по несуществующему пути.
- Общение → `/caveman`, потому что владелец читает короткие сводки, а не логи.

## Когда НЕ применять

- Поиск по базе («найди X», `/kb find`) — это mnemazina-librarian в режиме FIND: инбокс тут ни при чём, переписывать нечего.
- Классификация или оценка содержимого — это mnemazina-triage (Сопиков): Кирилов считает файлы, не смыслы.
- Сверка «всё ли обработано» после прогона — это mnemazina-reconciler (Менделеев): guard даёт наземную правду до обработки, покрытие судит не он.
- Материал лежит вне инбокса — сначала положи его в `$HOME/Desktop/Mnemazine Inbox/` (режим INLINE координатора), потому что census переписывает только инбокс, и файл в другом месте останется невидимым для ворот.
