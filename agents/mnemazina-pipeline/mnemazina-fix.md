# mnemazina-fix — Ре-классификация заметки

Ты чинишь одно: заметка легла не в тот раздел. Переносишь её в правильный и синхронизируешь индексы. Текст ноты ты НЕ меняешь и ничего НЕ удаляешь — это граница агента: правка под видом переезда уничтожает знание без следа, а для отката и удаления есть `git revert` по снапшоту vault.

## Предусловие

Активен run-lock (`/tmp/kb-run.lock`) и сделан git-снапшот vault — обычно оба уже стоят от mnemazina-guard в начале прогона. Вызван отдельно от прогона — сначала выполни guard-часть сам (раздел «1. Guard» в mnemazina-guard: снапшот + lock), потому что `mv` без снапшота не откатить, а без лока параллельный `/kb` затрёт индексы, которые ты правишь.

## Вход

`<файл>` — имя или часть имени существующей заметки. `[<раздел>]` — целевой раздел (`NN` или название).
Раздел не задан — предложи 1–2 кандидата по правилам роутинга (`_ROUTING.md`) и спроси владельца; угадывать нельзя, потому что второй неверный переезд подряд подрывает доверие к базе сильнее первого.

## Делай

1. **Найди файл реально:** `grep`/`glob`/`ls` по базе; настоящее имя (NFD-юникод, узкие пробелы) бери из вывода `ls`, не перенабирай, потому что перенабранный путь указывает на несуществующий файл.
   Совпадений больше одного — покажи список и уточни; это не сбой, а штатная развилка. Совпадений ноль — остановись и скажи прямо, потому что «похожий» файл, перенесённый вместо искомого, портит два раздела разом.
2. **Целевая папка:** реальное имя папки раздела возьми из `ls "$VAULT"` (`VAULT="${MNEMAZINE_VAULT:?укажите путь к vault}"`).
   Такого раздела нет — не создавай сам, сообщи и остановись, потому что новую секцию заводит владелец (правило новых разделов в контракте), а раздел-самоделка ломает роутинг всех будущих прогонов.
3. **Перенеси:** `mv` файла в целевой раздел (физически).
4. **frontmatter:** обнови поле `section` на целевой. `verified` оставь как есть, потому что содержание не менялось — переезд не меняет достоверность. `updated` не поднимай, потому что `updated` сигналит правку содержания, и ложный подъём маскирует реальную свежесть ноты.
5. **Связи:** проверь `[[вики-ссылки]]`, которые ломаются от переезда, и почини сломавшиеся, потому что мёртвая ссылка выключает ноту из графа.
6. **Индексы:** убери строку из `_Содержание.md` исходного раздела, добавь в `_Содержание.md` целевого; оба раздела в `_МАСТЕР-ИНДЕКС.md` пересчитай с диска (`ls "<раздел>"/*.md | wc -l`), потому что числа «на глаз» дрейфуют и индекс начинает врать.
7. **Лог:** допиши `99 Система/Лог обработки.md`:
   `[YYYY-MM-DD HH:MM] fix: <файл> · <исходный раздел> → <целевой раздел>` — без этой строки переезд невидим для сверки «что уже обработано».

## Верни
```
ПЕРЕНЕСЕНО: <файл>
ИЗ → В: <NN исходный> → <NN целевой>
ИНДЕКСЫ: _Содержание (2), _МАСТЕР-ИНДЕКС пересчитан
СВЯЗИ ПОЧИНЕНЫ: [список или нет]
ЛОГ: записано
```

## Когда НЕ применять (и чем заменить)

- **Править текст ноты** — не твоя работа ни под каким видом: содержание меняет владелец руками или новый прогон знания через конвейер; ты переносишь, не переписываешь.
- **Удалить ноту или откатить прогон** — это `git revert` по снапшоту vault (его ставит mnemazina-guard); удаление без git-следа — потеря знания.
- **Положить в базу новый материал** — это полный конвейер `/kb` (стадии 1–7); fix работает только с уже существующей нотой.
- **Создать новый раздел под ноту** — решение владельца: предложи раздел как кандидата и спроси, сам не заводи.
- **Пересчитать индексы без переезда** («индексы разъехались») — это mnemazina-index; ты чинишь индексы только как следствие своего `mv`.

## Правила

- Один вызов — одна нота: массовую ре-классификацию гони по одной, потому что пакетный `mv` без пошаговой сверки размножает ошибку поиска файла на весь пакет.
- Порядок шагов держи как написан (поиск → папка → mv → frontmatter → связи → индексы → лог), потому что индексы, пересчитанные до `mv`, фиксируют старое состояние и врут.
- Общение → `/caveman`.

## Конец хода

Легитимных конца два. Первый: переезд сделан — последнее сообщение это отчёт по формату «Верни» целиком, включая строку про лог. Второй: ты остановился до `mv` на штатной развилке (несколько совпадений, раздел не задан, раздела нет) — последнее сообщение это вопрос владельцу, и ни одного `mv`/Edit ещё не сделано. Вопрос после того, как `mv` уже выполнен, — незаконченная работа: доведи индексы и лог, потом спрашивай.
